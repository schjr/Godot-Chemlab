# Synchronous reconstructed recursive locks

`original_owned_recursive_locks.gd` provides real Godot `Mutex.lock()` and
`Mutex.unlock()` operations for recovered normal VCL wrapper calls. Every
binding requires an explicit reconstructed lifetime scope and nonzero DWORD
source pointer identity. It never copies historical CRITICAL_SECTION bytes,
initializes missing identities on demand, or substitutes a successful no-op.

The source audit is in `owned_critical_sections.md` and
`evidence/original-critical-wrapper-audit.json`: the bounded wrappers pass the
registry's embedded `+8` or graphic object's `+14` pointer to Enter/Leave;
Canvas construction aliases Brush/Pen/Font to the same `Canvas+38` lock. No
critical-section interior is read by that bounded original VCL code. Lookup and
release nest the already held registry lock, requiring recursion.

[Godot documents Mutex as reentrant](https://docs.godotengine.org/en/stable/classes/class_mutex.html),
with matching unlocks required before destruction.
[Windows critical sections](https://learn.microsoft.com/en-us/windows/win32/sync/critical-section-objects)
also provide recursive ownership by one thread and do not promise waiter order.
The new backend uses those documented normal ownership/blocking semantics;
it does not reproduce opaque Windows spin-count/debug/semaphore bytes or
Windows exception/deadlock-detection behavior.

## Explicit API and safety

- `create(scope,address)` creates one fresh Mutex. Duplicate bindings are
  rejected, including deleted bindings; source address reuse needs a new lifetime
  scope. Aliased source pointers within one scope therefore use the same lock.
- `enter(scope,address)` blocks on that actual Mutex on the calling OS thread.
  It returns success only after acquisition; recursive acquisition uses the same
  actual Mutex. Pending acquisitions prevent deletion.
- `leave(scope,address)` validates the current `OS.get_thread_caller_id()` and
  recursive depth before invoking actual unlock. Wrong-owner/unbalanced calls
  return explicit errors before undefined behavior.
- `destroy(scope,address)` rejects held or pending locks, then removes the Mutex
  reference only after balanced release. A tombstone prevents stale rebinding.
- `state(scope,address)` exposes ownership/depth/pending/deleted metadata, never
  the actual Mutex reference or captured lock internals.
- `dispatch(request,scope)` is a synchronous OriginalPen-compatible boundary
  for Enter/Leave only. Bind the explicit scope with
  `Callable(backend,"dispatch").bind(scope)`. Other primitive requests fail.

A separate metadata mutex guards binding lifecycle and ownership bookkeeping.
It is released before a potentially blocking lock acquisition. Release accounting
and actual unlock complete under that metadata gate so a new owner cannot
publish its state before the previous release is accounted for. No network
worker, queued ticket or fabricated completion is involved.

No implicit cleanup unlocks another thread's lock. Owners must finish every
successful entry before object/thread destruction. Exceptional exits through
unported Delphi SEH, abandoned owners, exact Windows scheduling, timeout/deadlock
exceptions, live actor mapping and original startup lifetimes remain outside
this isolated normal-path backend.

## Checks completed

`test_original_owned_recursive_locks.gd` passes using an actual separate Godot
Thread: recursive depth two, contender pending inside the blocking path,
continued exclusion after one unlock, acquisition only after the final unlock,
wrong-owner release rejection, held/pending deletion rejection, balanced worker
release, and stale-lifetime rejection. Cleanup releases main-thread debt before
joining; a bounded failure guard terminates the isolated test process rather
than force-unlocking another owner's Mutex or hanging indefinitely.

The separate actual-graph diagnostic is
`test_actual_pen_owned_recursive_locks.gd`. Its fixture is generated by
`tools/build_actual_pen_owned_locks.py`, pinned SHA256
`f75bb4c52ff082a9bccc0f5d2da09bd1af2d570d14bd43d2863e61fa888924f4`.
It uses the returned actual graph, capture SHA
`55efb5a1c8cba1556689dee25ca6bcc984b3740e80e47866fd100e9ef5ce7787`,
with explicit fresh reconstructed mutexes for the two needed identities.

The reference executes original PE instructions with **genuine fresh Python
`threading.RLock` operations** on its emulator-calling OS thread. This is a
reconstructed cross-platform primitive provider, not a Windows API execution
claim. All allocation/GDI/other primitive boundaries still refuse access.
An emulated-memory read hook rejects any original application read of the
historical lock interiors. Godot likewise masks every captured lock byte
unknown, including overlapping Canvas/registry spans, and checks those bytes
remain unknown after execution.

4. Leave nested lookup.
