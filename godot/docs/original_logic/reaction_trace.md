# Native reaction pass trace and bounded source port

`OriginalReaction` in `scripts/original/original_reaction.gd` ports the complete bounded reaction core `FUN_00462c18`: smart selection, ordinary one-way, general reversible iteration, and the special water iteration. It preserves original array order and dispatch. Unresolved inputs fail explicitly; there is no replacement concentration solver. The outer dissolution/thermal/quantity phases remain separate original modules.

## Driver and record layout

`FUN_0046c84c` (main/decompiled.cpp:33537) calls `FUN_0046b858` before and after the reaction core when vessel simulation word `0x3c74` equals 1. Otherwise it calls the core directly. This is dissolution/precipitation processing, not an unrelated extra reaction-rate multiplier.

Global reaction record and per-vessel reaction record share the following relative layout, with per-vessel base `vessel + 0xf20 + index*0xe8`:

| Relative offset | Vessel absolute offset | Meaning in the recovered code |
|---:|---:|---|
| 0x00 | 0xf20 | Leading integer, not stable textual equation identity |
| 0x04 | 0xf24 | Equation name |
| 0x08 / 0x0c | 0xf28 / 0xf2c | Reactant/product counts |
| 0x10 | 0xf30 | Ten reactant managed-string slots |
| 0x38 | 0xf58 | Ten product managed-string slots |
| 0x60 | 0xf80 | Ten int32 reactant coefficients |
| 0x88 | 0xfa8 | Ten int32 product coefficients |
| 0xb0 | 0xfd0 | Reaction heat double |
| 0xb8 | 0xfd8 | Condition string |
| 0xc0 | 0xfe0 | Rate double |
| 0xc8 | 0xfe8 | Equilibrium parameter double |
| 0xd0 | 0xff0 | Mode string |
| 0xd4 | 0xff4 | Equation-type string |
| 0xd8 / 0xdc / 0xe0 | 0xff8 / 0xffc / 0x1000 | Three optional note strings |

The smart-insertion copy at main/decompiled.cpp:30384 explicitly copies managed strings at relative 0xb8 and 0xd0–0xe0, integer/count/coefficients and three doubles. It calls `FUN_00462660` to ensure missing species slots. `FUN_0046c894` separately initializes missing names for all selected reactants and products with zero amounts, masses, volumes, binding labels and both solid counters.

The `.cem` loader persists only five tail parameters through 0xff0. It does **not** read 0xff4–0x1000. Subsequent raw-instruction tracing resolved the construction boundary: the loader explicitly constructs all fifty reaction records through `FUN_00416b30`, which zeros those managed-string pointers via `FUN_004016e8`. Therefore their cold-load state is empty, independent of allocator contents. See `constructor_trace.md` and `constructor_evidence.json`. The module still takes explicit `native_note` so callers distinguish cold-loaded records (empty) from smart-inserted library records (their copied third note). The library entry `方程式197` has third optional note `水的电离`; cold-load note inheritance is absent.


## Dispatch

The first loop (main/decompiled.cpp:30428–31002) runs records whose mode is not `可逆` and note at 0x1000 is not `水的电离`.

The second loop runs records whose mode is not `单向` and whose third note is not `水的电离`. The third loop runs records whose mode is not `单向` and whose note is `水的电离`. A blank or unexpected mode is not normalized to a textbook reversible/unidirectional meaning; it can qualify for more than one loop in the original code.

## Exact ordinary condition gates

`FUN_005410cc` wraps string equality (`FUN_00532208` and ZF); `FUN_005410e4` is inequality. These are not substring predicates.

The ordinary pass gates only these exact cases:

- `加热` or `加强热`: require vessel offset 0xa0 nonzero.
- `加强热`: additionally require temperature at 0x88 ≥200.
- `点燃`: this pass skips the record.
- First five GB18030 bytes equal `温度>` / `温度<`: parse the remaining bytes as a number; the comparisons accept equality at the threshold (≥ / ≤).

The ordinary pass has no separate gate for `水溶液`, `高温`, pH expressions or composite strings. Smart selection separately checks `高温` with heat and ≥200; that selection check must not be confused with the manual ordinary-pass check. Static PE string bytes and the original extended constants are retained in `reaction_constants.json`, generated by `tools/trace_original_reaction.py` with the executable's SHA-256.

`FUN_00452acc` finds the last ASCII `(` in a species name and copies from it until the first ASCII space or string end. Phase comparisons use this exact suffix, such as `(固体)` and `(气体)`, not heuristic charge/state classification.

## Rate and mutation order

The original speed setting at 0x3c78 is clamped to 1–19. Settings 1–9 map to 0.1×setting, 10 to 1, and 11–19 to setting−9. The retained 80-bit constant at 0x46b820 is decimal 0.1. The original time factor is caller-supplied global `_DAT_005636d4`; the module's `native_delta_seconds` must have that value, not an invented frame/time acceleration.

For every reactant entry, the native full-rate test compares amount to `coefficient * rate * time_factor * speed_factor`. If every entry is sufficient, it applies that full increment. Otherwise it starts with the first reactant amount divided by its coefficient and successively reduces the extent for each insufficient entry. It then subtracts/adds each stored entry in original order. Duplicate species are not aggregated, and no new nonnegative clamp is inserted. Degenerate zero-reactant/nonpositive-coefficient cases are outside this verified port and return unresolved.

Before those mutations, native phase scanning examines nonzero amounts >1e−10 and breaks on the first solid **or** gas reactant. This ordering matters: it does not independently classify all solids and all gases. Consumed solid entries reduce 0x3cd8 and 0x3ff8 according to the native min branch. Produced solid entries add to both counters only when field-9 liquid height is >1 and the preceding scan did not select a solid. Produced gases add to 0x3cc0 only when that scan did not select a gas.

`begin_reaction_cycle` clears 0x3cc0 once before all passes, matching the native core's initialization. It must not be called separately before each record. `step_one_way` does not recompute mass, volume, temperature, equilibration or settling; those remain the caller's native driver phases.

## Reversible and smart passes

General reversible iteration (decompiled.cpp:31003–32002) and water iteration (32003–33135) retain the native extent adjustment and halving sequence, phase activity formulas, ratio comparison and convergence threshold `0.0001 * K`. The source does not use the prototype bisection routine. `OriginalX87` retains extended intermediate arithmetic; `OriginalMath.pow_native` handles the original CRT power fallback after the native integer fast path. Invalid/undefined activity slots, unsupported floating-point range and iterations beyond the verification bound of10000 return unresolved.

Smart selection scans the original 599-record library in order. Species presence compares names, including zero-amount slots; duplicate comparison compares reactant/product names, not equation IDs or coefficients. Ten ASCII-space-separated condition tokens and fifty selected-record slots are original bounds. The original smart `温度<` branch uses the same greater-or-equal test as `温度>`; this behavior is preserved. Newly appended names get explicit zero amount/mass/volume/particle/binding slots by `626660`, with products preceding reactants. Existing particle slots retain their original values or unknown state.

## Verification

`tools/original_oneway_oracle.py` executes the original PE instructions through Unicorn with verified string/CRT boundaries. `tests/fixtures/original_reactions.json` contains47 machine cases, including original CEM selected records, manual ordinary gates and limits, reversible and water branches, smart selection, and two full599-record library searches. `tests/test_original_reaction_corpus.gd` compares species order, every final amount and gas/solid counters by stored IEEE754 bytes. All47 cases pass with zero mismatches in Godot4.7.1. This verifies the captured operand states, not every possible chemistry arrangement.

Fixture memory deliberately seeds numeric caches with zero and records their exact input bytes. That fixture input is not a constructor guarantee. `step_core` refuses missing existing particle caches, and dissolved/ion phase volumes that native code leaves unwritten remain explicit unknowns. Production may supply observed original runtime memory, but must not assume arbitrary allocator/stack contents are zero. Constructor facts are documented in `constructor_trace.md`.
