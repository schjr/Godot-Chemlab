# Container and catalogue dialogs

`LabDialogs.configure(owner, model)` attaches classic Godot dialogs using the parent interface theme. Historical captions for the three container tabs and editor titles come directly from the recovered forms in `data/forms.json`.

Container properties expose contents, manual reaction selections and rates, automatic reaction searches, smart reaction processing, ionic and extended equations, temperature, capacity, labels, hints, sealing and environmental conditions. Contents and reactions are edited immediately by the labelled action buttons; the settings tab commits on “确定”. “刷新” updates the lists after adding reagents from a separate window. Variable definitions emit the variable name, container ID, species and selected metric for graph integration.

The reagent chooser retains the original six filters. Dosing supports moles, grams converted using recovered molar mass, and milliliters converted using an explicit molar concentration. Milliliter dosing does not infer density. The reagent editor provides searchable phase filters, sorting, add/modify/delete actions, molar mass, valence, color and recovered solubility fields. Species keys cannot be renamed while modifying because experiment and equation references depend on them; display names can be changed. Referenced species cannot be deleted.

The reaction editor provides reactant/product search, ionic/reversible filters, sorting, add/modify/delete actions, and all documented equation parameters. Each reactant/product line specifies an exact library species followed by `|` and a positive stoichiometric coefficient. Unknown species and invalid coefficients are rejected. Reaction IDs cannot be renamed during modification. Deleting an equation removes its manual selection from existing containers.

“保存” writes both customized libraries to `user://catalogs.json`. “重新加载” validates and loads that file without replacing the apparatus state. Shipped libraries are never overwritten. The parent can call `load_custom_catalogs()` at startup and treats a missing file as normal. Original solubility fields remain available to edit; the reconstructed simulation does not claim a recovered solubility algorithm.

`tests/test_dialogs.gd` constructs all four dialogs and checks chemistry-entry validation. `tests/test_workflows.gd` instantiates the complete main scene, imports all 28 original experiments, executes the three recovered programs with real chemistry bindings, doses the original titration, roundtrips complete workspace JSON, verifies the pH variable signal mapping and live chart data, and exercises copy/paste and pouring through the application actions. Both tests return a nonzero exit code on failure; the workflow test also has a 15-second timeout guard.
